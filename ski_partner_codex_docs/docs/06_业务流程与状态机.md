# 业务流程与状态机

## 1. 核心流程

```text
用户登录
  ↓
完善个人资料
  ↓
浏览滑雪局 / 发布滑雪局
  ↓
申请加入
  ↓
发起人审核
  ↓
审核通过后成为成员
  ↓
进入局内消息
  ↓
线下滑雪
  ↓
发起人结束滑雪局
  ↓
成员互评
  ↓
沉淀信用
```

## 2. 滑雪局状态

| 状态 | 说明 |
|---|---|
| recruiting | 招募中 |
| full | 已满员 |
| finished | 已结束 |
| cancelled | 已取消 |
| removed | 管理员下架 |

状态流转：

```text
recruiting → full
recruiting → cancelled
recruiting/full → finished
recruiting/full → removed
```

规则：
- 当前成员数达到 max_members 时，自动变为 full。
- cancelled 之后不可申请。
- finished 之后不可申请，只能评价。
- removed 之后普通用户不可见。

## 3. 加入申请状态

| 状态 | 说明 |
|---|---|
| pending | 待审核 |
| approved | 已同意 |
| rejected | 已拒绝 |
| cancelled | 申请人取消 |

状态流转：

```text
pending → approved
pending → rejected
pending → cancelled
```

规则：
- 同一用户对同一滑雪局只能有一个 pending 或 approved 申请。
- 发起人不能申请自己的滑雪局。
- 满员后不可申请。
- 同意申请后，写入 event_members。
- 同意申请后，current_members + 1。
- 达到人数上限后，滑雪局状态变为 full。

## 4. 成员状态

| 状态 | 说明 |
|---|---|
| active | 正常 |
| left | 已退出 |
| removed | 被移除 |

规则：
- 发起人不能退出，只能取消滑雪局。
- 已结束的局不能退出。
- 成员退出后，current_members - 1。
- 如果原状态是 full，退出后变回 recruiting。

## 5. 评价规则

- 只有同一个滑雪局的成员之间可以评价。
- 只能在滑雪局状态为 finished 后评价。
- 同一评价人对同一被评价人，在同一滑雪局下只能评价一次。
- 发起人和成员都可以互评。
- 评价影响用户信用评分和好评率。

## 6. 举报规则

- 登录用户可以举报用户、滑雪局、消息、评价。
- 举报后进入后台待处理。
- 管理员可以处理为：
  - resolved 已处理
  - rejected 不成立
- 管理员可对用户禁用，对滑雪局下架，对评价隐藏。

## 7. 安全规则

- 未登录不能发布、申请、聊天、评价。
- 未完善资料不能发布或申请。
- 被禁用用户不能登录业务功能。
- 被拉黑功能第一版可预留表结构，MVP 可不实现。
- 手机号认证、实名认证第一版可以预留字段，暂不强制。
