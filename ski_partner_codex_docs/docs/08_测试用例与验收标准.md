# 测试用例与验收标准

## 1. 首页

### 用例 1：正常加载列表
操作：
- 打开首页

预期：
- 显示滑雪局列表
- 卡片展示标题、日期、雪场、人数、标签、发起人

### 用例 2：筛选雪场
操作：
- 选择雪场“万龙”

预期：
- 只展示万龙相关滑雪局

### 用例 3：筛选日期
操作：
- 选择某一天

预期：
- 只展示该日期滑雪局

### 用例 4：空状态
操作：
- 筛选一个没有数据的条件

预期：
- 显示空状态和发布滑雪局按钮

## 2. 发布滑雪局

### 用例 1：必填校验
操作：
- 不填雪场/日期/人数，点击发布

预期：
- 提示对应字段必填

### 用例 2：正常发布
操作：
- 填写完整信息并提交

预期：
- 创建成功
- 跳转滑雪局详情
- 当前用户成为发起人和成员

### 用例 3：人数限制
操作：
- maxMembers 填 1 或小于当前成员数

预期：
- 提示人数不合法

## 3. 申请加入

### 用例 1：未登录申请
操作：
- 游客点击申请加入

预期：
- 跳转登录

### 用例 2：发起人申请自己的局
操作：
- 发起人点击申请加入

预期：
- 不允许申请

### 用例 3：满员申请
操作：
- 对 full 状态滑雪局申请

预期：
- 提示已满员

### 用例 4：重复申请
操作：
- 同一个用户重复申请同一滑雪局

预期：
- 如果已有 pending/approved，禁止重复申请

## 4. 审核申请

### 用例 1：发起人同意申请
操作：
- 发起人同意 pending 申请

预期：
- 申请状态变为 approved
- 成员表新增记录
- 当前人数 + 1

### 用例 2：非发起人审核
操作：
- 普通成员调用审核接口

预期：
- 返回无权限

### 用例 3：同意后满员
操作：
- 同意申请后达到人数上限

预期：
- 滑雪局状态变为 full

## 5. 局内消息

### 用例 1：成员查看消息
操作：
- 成员进入局内群聊

预期：
- 可以看到消息列表

### 用例 2：非成员查看消息
操作：
- 非成员进入群聊

预期：
- 返回无权限

### 用例 3：发送文本
操作：
- 成员发送文本

预期：
- 消息保存成功
- 列表可见

## 6. 滑后评价

### 用例 1：未结束不能评价
操作：
- recruiting 状态下评价

预期：
- 提示滑雪局未结束

### 用例 2：非同局成员评价
操作：
- 无关用户评价

预期：
- 返回无权限

### 用例 3：重复评价
操作：
- 同一评价人重复评价同一人

预期：
- 禁止重复评价

### 用例 4：评价成功
操作：
- 提交评分和标签

预期：
- 评价创建成功
- 被评价人信用数据更新

## 7. 后台管理

### 用例 1：下架滑雪局
操作：
- 管理员下架一个滑雪局

预期：
- 状态变为 removed
- 前台列表不可见

### 用例 2：处理举报
操作：
- 管理员处理举报

预期：
- 举报状态变为 resolved 或 rejected

## 8. 验收标准

### 前端
- 所有页面可以正常打开
- 表单校验完整
- 空状态、加载状态、错误状态完整
- 移动端样式不溢出
- 页面跳转顺畅

### 后端
- 所有接口可启动、可调用
- SQL 可初始化
- 状态流转正确
- 权限校验正确
- 返回格式统一

### 数据
- 有至少 10 条滑雪局示例数据
- 有至少 5 个用户示例数据
- 有雪场字典和标签字典

### 文档
- 提供启动说明
- 提供接口说明
- 提供初始化 SQL
