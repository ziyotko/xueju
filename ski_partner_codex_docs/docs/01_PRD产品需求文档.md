# PRD 产品需求文档

## 1. 产品名称

雪局

## 2. 产品定位

专注滑雪组局的搭子工具。用户可以按照雪场、日期、出发地、滑雪水平、单双板、玩法偏好，快速发布或加入滑雪局。

## 3. 目标用户

### 3.1 主要用户
- 周末滑雪用户
- 北京、长春、吉林、乌鲁木齐、成都等滑雪城市用户
- 想找同水平滑雪伙伴的人
- 有拼车、拼房、互拍需求的人
- 新手找安全同行者，进阶用户找同水平刷道搭子

### 3.2 首发城市建议
第一版建议只聚焦一个城市，推荐：
- 北京 → 崇礼、南山、怀北、渔阳
- 或吉林/长春 → 北大湖、松花湖

MVP 默认使用北京出发作为示例数据。

## 4. 核心用户场景

### 场景 1：我这周六想去滑雪，缺一个搭子
用户打开首页，筛选「周六、北京出发、万龙、中级、单板」，看到合适的滑雪局，提交加入申请。

### 场景 2：我自己开车，可以带 1-2 人拼车
用户发布滑雪局，填写出发地、车辆座位、费用说明，其他用户申请加入。

### 场景 3：女生只想找同性搭子
发布或筛选滑雪局时选择「仅同性」或「女生局」，降低线下陌生人风险。

### 场景 4：滑完以后沉淀信用
用户完成滑雪局后进行互评，形成准时、友好、水平真实、不爽约等标签。

## 5. 产品边界

### 第一版做
- 发布滑雪局
- 浏览滑雪局
- 筛选滑雪局
- 申请加入
- 发起人审核
- 局内简单消息
- 我的行程
- 用户资料
- 滑后评价
- 举报与拉黑预留
- 管理后台基础审核

### 第一版不做
- 支付
- 雪票买卖
- 保险
- 押金
- 复杂 IM
- 轨迹记录
- 视频社区
- 教练入驻
- 直播
- 附近的人
- 情感交友

## 6. 核心指标

- 发布滑雪局数量
- 加入申请数量
- 成功成局数量
- 滑后评价完成率
- 次周复用率
- 举报率
- 爽约率

## 7. 产品原则

1. 强行程，不强社交。
2. 强匹配，不强聊天。
3. 强安全，不做擦边交友。
4. 先小城市/小雪场验证，不一开始全国铺开。
5. 先人工运营跑通，再做自动增长。

## 8. 主要角色

### 普通用户
- 浏览滑雪局
- 发布滑雪局
- 申请加入
- 发送局内消息
- 评价他人
- 举报异常行为

### 发起人
- 创建滑雪局
- 审核加入申请
- 管理成员
- 发布集合信息
- 结束滑雪局

### 管理员
- 管理用户
- 管理滑雪局
- 处理举报
- 管理评价
- 管理基础字典
