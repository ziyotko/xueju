# Codex 总提示词

你现在是一个资深全栈开发工程师。请基于以下文档，为我开发一个名为「雪局」的滑雪搭子/滑雪组局小程序 MVP。

## 一、项目目标

开发一个专注滑雪组局的工具，不做泛社交，不做复杂社区。核心目标是让用户可以按雪场、日期、水平、出发地快速找到靠谱雪友，一起滑雪、拼车、拼房、互拍视频。

## 二、技术栈要求

### 小程序端
- 微信小程序原生开发，或 uni-app 编译到微信小程序。如果你判断已有项目技术栈不同，请优先沿用项目现有技术栈。
- 页面风格参考 `assets/ui_mockup.png`。
- UI 风格：干净、年轻、运动感、蓝紫渐变、圆角卡片、弱阴影。

### 后端
- Go + Gin
- MySQL
- JWT 登录鉴权
- RESTful API
- 文件上传接口预留
- 后台管理接口预留

### 管理后台
- Vue3 + Element Plus
- 用于管理用户、滑雪局、举报、评价、基础字典。

如果当前仓库已有技术栈，以现有项目结构为准，不要强行重构。

## 三、开发原则

1. 先完成 MVP 闭环，不要扩展复杂功能。
2. 优先保证页面能跑通、数据结构清晰、接口可联调。
3. 所有状态值使用常量或枚举，不要写魔法字符串。
4. 所有接口返回统一格式。
5. 所有表必须包含 created_at、updated_at，必要时包含 deleted_at。
6. 需要提供初始化 SQL、示例数据和接口测试用例。
7. 移动端页面必须适配主流微信小程序屏幕。
8. 代码中需要保留清晰注释，便于后续继续迭代。

- 个人主页
- 滑后评价
- 登录/资料编辑

### 后端模块

- 局内消息模块
- 评价模块
- 举报模块
- 字典模块
- 后台管理基础模块

### 后台管理
- 用户列表
- 滑雪局列表

## 五、不要做的功能

第一版不要做：
- 雪票交易
- 二手装备
- 轨迹记录
- 复杂社区信息流
- 短视频
- 直播
- 支付
- 押金
- 保险购买
- 附近的人
- 情感交友推荐
- 复杂即时通讯

## 六、接口风格

统一返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

分页返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "page": 1,
    "pageSize": 10,
    "total": 0
  }
}
```

## 七、你需要输出什么

请直接修改/生成代码，并按阶段提交：

1. 数据库建表 SQL
2. 后端 model、dao/repository、service、controller、router
3. 小程序页面、组件、请求封装、状态枚举
4. 管理后台页面
5. 示例数据
6. 接口测试说明
7. 启动说明

优先完成可运行 MVP，不要只输出设计方案。
